Foundational Concept

What is OT, and Why Does It Need Its Own Tool?

Most cybersecurity software was built for Information Technology (IT): laptops, cloud data centers, and corporate databases. But water utilities, electrical substations, and factories run on Operational Technology (OT).

🏢

Standard IT Environment

  • • Priority: Data confidentiality. If an IT server reboots to apply a patch, users wait 5 minutes.
  • • Hardware: Powerful multi-core Intel/AMD servers with tens of gigabytes of RAM.
  • • Scanning: IT scanners blast thousands of network packets per second to map open ports.
🏭

Industrial OT Environment (PLCs & SCADA)

  • • Priority: Physical Safety & Process Continuity. A 50-millisecond network delay can trip an emergency valve or halt a refinery cracker.
  • • Hardware: Ruggedized microcontrollers installed in 2008 running low-power 16MHz embedded chips that are never rebooted.
  • • Scanning: An IT port scan can freeze the controller and crash the plant!
💡 Real-World Analogy: The Train Horn in the Library

Imagine walking into an office building and blowing a whistle to see who looks up. In IT, everyone turns their head, responds, and goes back to work. But in an industrial plant, the computers are like delicate brain surgeons operating under strict microsecond timing. If you blast them with sudden noise (an IT port scan), their communication buffers overflow, and the machine locks up in an unrecoverable fault state.

Safety & Probing Methodology

Selective Probing: How SHANK Discovers Assets Safely

Michael Thompson invented the concept of Selective Probing for SHANK. Instead of knocking on the door of sensitive controllers, SHANK queries the network infrastructure (the industrial switches and routers) who is plugged in.

❌ Dangerous: IT Ping Sweeps

Sends thousands of unexpected packets directly to PLCs.

[Scanner] ---> ICMP Echo Request ---> [PLC CPU]
[Scanner] ---> TCP SYN Port 80 ---> [PLC Buffer Overflows!]
[Scanner] ---> TCP SYN Port 443 ---> [PLC Faults - Red LED]
RESULT: PLANT PRODUCTION LINE TRIPS AND HALTS

✓ Safe: SHANK Selective Probing

Interrogates industrial managed switches; leaves PLCs undisturbed.

[SHANK] ---> SNMP Query ---> [Cisco / Moxa Switch]
[Switch] ---> "Port 1 has MAC 00:1D:9C..." ---> [SHANK]
[Switch] ---> "Port 2 is connected to PLC 2" ---> [SHANK]
RESULT: 100% INVENTORY WITH ZERO PLC PACKETS

🔬 Technical Deep Dive: The Protocols Used

SHANK interrogates switches using read-only SNMP queries against standardized Management Information Bases (MIBs):

RFC 1213 / 2863 (ifTable / ifXTable)

Queries interface operational status, link speed (10/100/1000 Mbps), duplex mode, and port descriptions.

RFC 1493 / 4188 (Bridge MIB)

Extracts the Forwarding Database (FDB: dot1dTpFdbTable), revealing which MAC addresses were learned on which physical switch port.

Deterministic Resolution

Deterministic Layer 1 Link Resolution: No Guessing

When an alarm sounds, technicians shouldn't have to trace a physical patch cable through 200 feet of dusty cable conduit. SHANK deterministically proves which switch port each asset is plugged into.

Step 1: Interrogate Switch

SHANK asks the managed switch for its learned MAC address table across all ports.

Step 2: Filter Uplinks

Using LLDP and CDP, SHANK ignores ports connecting switch-to-switch (trunks).

Step 3: Pin the Asset

If port Fa1/1 only sees MAC 00:1D:9C..., that port is mathematically bound to PLC-01-MAIN.

What happens when someone plugs in a cheap unmanaged switch?

In factories, technicians often plug in an unmanaged 5-port hub (like a Moxa EDS-205) inside a machine skid. These hubs have no IP address and no SNMP.

SHANK's Hybrid Detection: When SHANK sees 4 different MAC addresses appearing on a single managed port (and it's not a trunk), it detects that an unmanaged switch is hidden there. It automatically creates a "Virtual Hub" and renders the connections with dashed audit lines so engineers know a shadow device exists.
Multi-Dimensional Context

The "Clone Machine" Problem: Duplicate IP Addresses

In corporate IT, every device has a unique IP address. In factories, OEMs build identical machine skids with identical IP addresses (e.g. 192.168.1.50).

💡 Real-World Analogy: Apartment 4B

If you mail a letter addressed simply to "Apartment 4B", the post office cannot deliver it. Millions of buildings have an "Apartment 4B". You need the full address: Country, City, Street, Building Number, and Apartment Number. That is exactly what SHANK's 5-Tier Location Tree does for industrial assets.

Chapter 1 // Systems Specification

Executive Summary & Cyber-Physical Dilemma

ISA/IEC 62443-3-2 & NIST SP 800-82r3 Foundations

Operational Technology (OT) and Industrial Control Systems (ICS/SCADA) underpin global critical infrastructure. In industrial facilities, network context encompasses significantly more than an enumerated list of Internet Protocol (IP) addresses. Comprehensive context requires capturing physical Layer 1 patch interconnections, Layer 2 data link switching states, Layer 3 routing boundaries, automation backplane chassis configurations, functional process dependencies, and dynamic traffic flows.

Active IT Scanning Vulnerabilities Traditional active scanners (Nmap, Nessus) execute rapid SYN/UDP/ICMP sweeps. Against legacy PLCs, these floods exhaust embedded microcontrollers and saturate low-bandwidth fieldbuses (RS-485, Modbus RTU), triggering communications timeouts, CPU faults, and unplanned plant trips.
Passive DPI Blind Spots Purely passive network monitors (SPAN/TAP) only observe assets when they transmit over IP. They remain completely blind to dormant cold-standby controllers, disconnected engineering laptops, and physical backplane chassis sub-modules (slots 0–16) communicating across proprietary backplanes.

SHANK (**S**CADA & **H**ardware **A**sset **N**etwork **K**nowledge) implements an infrastructure-centric philosophy. Rather than probing sensitive PLCs directly, SHANK interrogates managed network switches and automation backplanes via deterministic protocols.

Chapter 3 // Network Context Acquisition

Deterministic Layer 1 Physical Link Resolution

SNMP Bridge MIB dot1dTpFdbTable & Elimination Algorithm

Tracing physical patch cables without walking the plant floor requires interrogating managed switches via SNMP read-only community strings across four standardized MIBs:

RFC 1213 / 2863 (ifXTable)
Interface speeds, duplex, administrative status, and descriptions.
RFC 1493 / 4188 (dot1dTpFdbTable)
Bridge forwarding database mapping learned MACs to physical port indices.
RFC 1213 (ipNetToMediaTable)
Switch ARP cache resolving Layer 2 MACs to active IPv4 addresses.
IEEE 802.1AB / CDP (lldpRemTable)
Neighbor discovery isolating switch-to-switch trunk uplinks.

Mathematical Resolution Logic

Let $L(p)$ be the set of learned MAC addresses on switch port $p$:

If |L(p)| == 1 and p not in Trunk_Uplinks:
    MAC m = L(p)[0]
    IP ip = ARP_Cache(m)
    Deterministic_Binding = <Switch: s, Port: p, Asset: Match(m, ip)>
Else if |L(p)| > 1 and p not in Trunk_Uplinks:
    Trigger Hybrid Unmanaged Switch Modeling (Synthesize Virtual Hub)

Chapter 6 // Data Modeling

Multi-Dimensional Context & Duplicate IP Disambiguation

5-Tier Location Trees & Shared Trunk Switch Risk Analysis

Turnkey OEM machine skids (e.g. reverse osmosis units, bottling lines) frequently reuse standardized RFC 1918 private subnets (e.g., 192.168.1.50). Standard IT databases use IP address as the primary key, resulting in database collisions.

SHANK disambiguates assets using an immutable 5-Tier Location Tree:

Enterprise → Site → Building → Room / Area → Cabinet / Enclosure

Asset Key = <LocationPath, SwitchPortBinding, MAC Address>

This allows identical IP addresses to coexist cleanly across independent skids. Furthermore, the engine cross-checks functional OT Systems to identify Shared Trunk Switch Exposures—alerting when two isolated process lines route traffic across the same unsegmented switch trunk.

Chapter 8 // Cybersecurity Risk Mathematics

Michael Thompson Contextual OT Risk Formula

Hardware Write-Protect Key Switch Discounts & Compensating Defenses

In industrial operations, raw CVSS scores cause alarm fatigue. SHANK applies Michael Thompson's contextual risk formula:

OT Risk Score = min(10.0, [Base CVSS * F_Purdue * F_Criticality * F_KeySwitch] / product(1 - D_k))
  • Physical Key Switch Discount: Rotating the controller key switch to RUN hardware write-protects memory, discounting vulnerability exploitability by 30% (Factor: 0.70).
  • Purdue Factor: Level 1 (0.80) vs Level 3.5 (1.20).
  • Process Criticality: Safety Critical SIS (1.30) vs Low Non-essential (0.80).
