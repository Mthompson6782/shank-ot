Foundational Concept

What is OT, and Why Does It Need Its Own Tool?

Most cybersecurity tools were designed for Information Technology (IT): office laptops, cloud servers, and smartphones. But factories, water treatment facilities, and power grids run on Operational Technology (OT).

🏢

Standard IT Environment

  • • Priority: Confidentiality first. If a server reboots to apply a patch, users wait 5 minutes.
  • • Hardware: Powerful multi-core Intel/AMD servers with gigabytes of RAM.
  • • Scanning: IT scanners blast thousands of network packets per second to find open ports.
🏭

Industrial OT Environment (PLCs & SCADA)

  • • Priority: Availability and Physical Safety. A 50-millisecond delay can trigger an emergency valve shutdown or damage a multimillion-dollar turbine.
  • • Hardware: Ruggedized microcontrollers installed in 2008 running low-power 16MHz chips that never reboot.
  • • Scanning: An IT port scan can freeze the controller and crash the plant!
💡 Real-World Analogy: The Train Horn in the Library

Imagine walking into an office building and blowing a whistle to see who looks up. In IT, everyone turns their head, responds, and goes back to work. But in an industrial plant, the computers are like delicate brain surgeons operating under strict timing. If you blast them with sudden noise (an IT port scan), their hands shake, the communication buffer overflows, and the machine locks up in an unrecoverable fault state.

Ralph Langner invented the concept of Selective Probing for OTbase. Instead of knocking on the door of every sensitive controller, we ask the network infrastructure (the industrial switches and routers) who is plugged in.

🔬 Technical Deep Dive: The Protocols Used

SHANK interrogates switches using read-only SNMP queries against standardized Management Information Bases (MIBs):

RFC 1213 / 2863 (ifTable / ifXTable)

Queries interface operational status, link speed (10/100/1000 Mbps), duplex mode, and port descriptions.

RFC 1493 / 4188 (Bridge MIB)

Extracts the Forwarding Database (FDB: dot1dTpFdbTable), revealing which MAC addresses were learned on which physical switch port.

Deterministic Resolution

Deterministic Layer 1 Link Resolution: No Guessing

When an alarm goes off, an automation technician shouldn't have to trace a cable through 200 feet of dusty cable tray. SHANK deterministically proves which physical switch port each device is plugged into.

Step 1: Interrogate Switch

SHANK asks the managed switch for its learned MAC address table across all ports.

Step 2: Filter Uplinks

Using LLDP and CDP, SHANK ignores ports connecting switch-to-switch (trunks).

Step 3: Pin the Asset

If port Fa1/1 only sees MAC 00:1D:9C..., that port is mathematically bound to PLC-01-MAIN.

What happens when someone plugs in a cheap $30 unmanaged switch?

In factories, technicians often plug in an unmanaged 5-port hub (like a Moxa or Stratix 2000) inside a machine skid. These hubs have no IP address and no SNMP.

SHANK's Hybrid Detection: When SHANK sees 4 different MAC addresses appearing on a single managed port (and it's not a trunk), it detects that an unmanaged switch is hidden there. It automatically creates a "Virtual Hub" and renders the connections with dashed audit lines so engineers know a shadow device exists.
Multi-Dimensional Context

The "Clone Machine" Problem: Duplicate IP Addresses

In corporate IT, every device has a unique IP address. In factories, OEMs build identical machine skids with identical IP addresses (e.g. 192.168.1.50).

💡 Real-World Analogy: Apartment 4B

If you mail a letter addressed simply to "Apartment 4B", the post office cannot deliver it. Millions of buildings have an "Apartment 4B". You need the full address: Country, City, Street, Building Number, and Apartment Number. That is exactly what SHANK's 5-Tier Location Tree does for industrial assets.

How SHANK Solves the Conflict

Skid 1: Filtration Machine
Location: Plant-North / Building-A / Room-1 / Cabinet-CP01

Skid 2: Chemical Dosing Machine
Location: Plant-North / Building-B / Room-4 / Cabinet-CP02
IP Address: 192.168.1.50
Switch Port: SW-02 Port Fa1/1

In standard IT databases, Skid 2 would overwrite Skid 1. In SHANK, both assets live happily side-by-side because they are anchored by their location path and physical switch port.

Reconciliation Engine

Fusing Armis Passive Radar with OTbase Ground Truth

Armis is an incredible platform that listens passively to network traffic. But what happens when passive listening disagrees with physical reality?

The 4 Discrepancy Audits Performed Automatically

1. Rogue Assets (CRITICAL)

Armis detects a Wi-Fi maintenance tablet communicating with a PLC over port 44818. It is NOT in the authorized engineering baseline. Immediate quarantine!

2. Firmware Drift (HIGH)

Armis inferred firmware "v32" based on packet headers. But our CIP backplane crawler confirmed the physical card is running "v33.011".

3. Port Conflicts (MEDIUM)

Armis thought the device was on Port 9, but switch SNMP Bridge MIB proves it is on Port 4. Flags where patches were moved.

4. Dormant Assets (MEDIUM)

A safety flowmeter exists in the engineering blueprints, but Armis saw 0 packets. Proves a device is offline or unmonitored.
